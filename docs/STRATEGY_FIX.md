# 首手王炸修复与回归验证

日期：2026-09-21。对照版本：`18f265a`。使用原有 Laya multilingual FP16 权重，没有重新训练。

## 原因和复现

问题位于策略层：旧 `shape_cost` 将双王计算为两手单牌，低估保留王炸的价值；炸弹消耗惩罚较轻，地主首手又没有保留控制牌的候选边界。模型可以合法选择一个策略层错误放行的动作。

用 `Game(random.Random(12))` 并让当前首叫者叫 3 分，地主手牌为：

```text
3, 5, 6, 7, 8, 8, 9, 10, 10, 10, J, J, Q, K, K, A, A, 2, 小王, 大王
```

旧版本王炸综合分约 -15.949，顺子 5–Q 约 -16.083，两者均被允许。新增“王炸是一手”和“散牌地主首手不空炸”测试先在旧实现失败，再修改代码。

这复现的是错误放行，不是声称该种子每次实际推理都会出王炸。本次真实模型对照中，旧版本选择顺子 5–Q，新版本选择单张 3；两者都合法。用户原始牌局没有保存，无法逐牌重放。

## 改动和边界

- 拆牌估算加入保留王炸的一手方案，同时保留拆王方案供比较。
- 增加拆双王、拆炸弹、领出空炸和提前消耗大单的条件代价；对手剩 1/2 张时减弱，避免妨碍紧急防守。
- 地主第一手存在不拆控制牌的普通领出时，排除空炸候选；全部是炸弹的特殊牌局不会被强迫拆炸。
- 直接出完最高优先。王炸后剩一手合法牌可确定收尾；普通炸弹需要根据已知牌和剩余张数排除未知更大炸弹与王炸才同样优先。此检查保守地高估其他玩家的控制牌，不读取隐藏手牌。
- 模型提示补充控牌、组织低牌、协作原则；提示功能也按允许候选排序。
- 发牌生产逻辑保持系统随机洗牌，新增固定排列测试，确认不会因一家牌太好而交换或重洗。

这些经验不能证明最优策略，也不意味着所有领出都应选择最小单张。来源与候选原则见 [策略调研](STRATEGY_PRINCIPLES.md)。

## 验证结果

真实 GPU 测试命令（模型路径按本机配置替换）：

```bash
LAYA_TEST_MODEL=/absolute/path/to/model .venv/bin/python -B -m unittest discover -s tests -v
```

**45 项全部通过**，其中 3 项调用真实模型；不配置模型时跳过这 3 项。覆盖首手保留王炸、王炸一手计数、确定收尾、紧急拦截、普通炸弹未知控制检查、全炸弹手牌例外、发牌不按强度重排，以及原有规则/HTTP/信息隔离。

种子 0–299，均让随机首叫位直接叫 3 分：44 副地主牌持双王。旧版本有 14 副允许首手王炸，新版为 0。只改正王炸手数的中间版本也是 0，支持手数估计是此回归的重要原因。这里统计的是允许候选，既不是模型实际王炸次数，也不是胜率。

另用相同种子 4000–4011 对比新旧版本各 12 局。固定席位 0 为启发式地主，席位 1/2 共用真实 Laya；对手评分函数冻结为 `18f265a`，防止修改对手造成口径漂移。新旧策略共用相同模型实例、权重和 6 个隐藏牌样本设置，各自仍按本局公开历史重新采样。

| 指标 | 旧版本 | 新版本 |
| --- | ---: | ---: |
| AI 农民阵营获胜 | 9/12 | 9/12 |
| 完成牌局 | 12/12 | 12/12 |
| 模型出牌调用 | 261 | 254 |
| 平均整步耗时 | 51.3 ms | 56.9 ms |
| 最大整步耗时 | 97.9 ms | 190.3 ms |

这 24 局只复用了 12 副牌，样本较小；结果支持本次未观察到胜率退化，不支持声称整体牌力显著提升。评测固定地主，不评估叫分能力。计时包含策略处理和推理，排除首次加载、HTTP 和界面延迟。

发牌另做 50,000 次固定种子和 2,000 次系统随机审计，未发现席位偏置证据；极端高牌差属于随机分布允许的波动，详见 [发牌审计](DEAL_AUDIT.md)。

测试服务完成后关闭，基准及审计仅在内存中运行，没有保存测试对局、临时旧代码副本或模型副本。
