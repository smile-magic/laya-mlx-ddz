# 验证记录与策略边界

验证日期：2026-09-21。硬件：Apple M4 / 32 GB，macOS 27.0。Python 3.14.7，真实 Laya multilingual FP16，模型没有重新训练。

## 验收范围

最终版本完成 36 项自动测试，开启 `LAYA_TEST_MODEL` 后全部通过，其中 2 项直接运行真实 GPU 模型。常规运行跳过这 2 项，其余不依赖 MLX。

- 14 类牌型及非法组合、飞机重复单翼、主体/长度比较、王炸与炸弹优先级。
- 35 副固定随机手牌：全部生成动作必须属于手牌、无重复且具有一致的规范牌型；另用独立计数判定器穷举三组小手牌子集，核对完整生成结果。
- 40 局固定发牌的完整启发式对局：每次行动核对全部 54 张牌守恒、180 次行动内结束、结算零和。
- 叫分递增、3 分立即结束、全过重发与首叫位轮换、连续两次过牌后重新领出、非法请求不改变状态。
- 农民任一玩家出完立即全队获胜；春天、反春天、炸弹倍数分别验证。
- 玩家观察对象不随不可见手牌互换而变化；采样守恒并满足公开底牌约束；浏览器响应不含对手手牌、采样牌或未执行候选。
- 立即出完强制执行、保护队友牌权、阻挡地主最后单张、避免向最后单张对手送牌、拆牌手数、候选窗口回归。
- HTTP 版本冲突拒绝重复行动；模型忙、模型报错均保持当前回合；恢复后可重试；外部来源请求被拒绝。
- 真实模型叫分及三个席位出牌；实际 tokenizer 解码检查最后状态说明与每个候选末尾特征没有截断。

另从 PyPI 临时安装了 README 固定的 `laya-mlx==0.1.0` 发布包（不使用工作区可编辑版本），同样通过全部 36 项测试，包括真实 GPU 测试；临时安装目录随后删除。

模型故障测试中终端出现的 `simulated model failure` 是主动注入的预期错误，测试确认回合原样保留，并随后完成重试。

## 策略调试发现

初版允许模型在距最高综合分 0.65 内选择。对 seeds 1000–1019 的分席位评测发现，地主上家的农民仅赢 6/20；在同一组局面直接执行策略最高分可赢 12/20。这里不是数据泄漏或非法出牌，而是宽泛的“分数接近”掩盖了不同的模拟团队收益。

已提取固定局面写成回归，先确认失败，再收紧允许条件：

1. 综合分距最高分不超过 0.20；
2. 即时失败风险不高于最高分候选；
3. 模拟收益下降不超过半个样本权重，即 `0.5 / samples`；
4. 直接出完始终强制保留。

这些阈值是工程启发式，不是理论最优参数。用于发现问题的 1000–1019 牌局已成为开发集，不再作为最终未见局面证据。

## 最终版本：新牌局、按角色对照

命令：

```bash
.venv/bin/python -B tools/benchmark.py --model models/laya --seeds 20 --start-seed 2000
```

每副牌固定席位 0 为地主（3 分），先跑三席位都是基础启发式的基线，再依次仅替换一个席位为当前 Laya 组合策略。其余席位仍按同一个 `move_score` 基础启发式出牌。三种角色复用 20 副牌，不能把 60 局当作 60 个独立发牌样本。

| 被替换角色 | 当前组合策略的阵营获胜 | 同牌全启发式基线的该阵营获胜 |
| --- | --- | --- |
| 地主（席位 0） | 14 / 20 | 9 / 20 |
| 地主下家农民（席位 1） | 14 / 20 | 11 / 20 |
| 地主上家农民（席位 2） | 17 / 20 | 11 / 20 |

60 局全部完成，无非法动作或超出行动上限。共 674 次真实 Laya 出牌调用、254 次策略护栏介入。平均整步 53.9 ms，最大 389.3 ms；最大输入 529 tokens，低于 checkpoint 的 1024 上限。

时间包含候选生成、采样模拟、分词和同步推理，排除模型首次加载、HTTP 和页面为可读性增加的短暂停顿。没有只统计神经网络前向时间来掩盖策略开销。

## 两个 AI 共享模型的完整牌局

命令：

```bash
.venv/bin/python -B tools/benchmark.py --model models/laya --mode table --seeds 12 --start-seed 3000
```

席位 1 与 2 由同一 Laya 实例控制，分别输入各自独立视角；席位 0 是基础启发式地主。

- 12 局全部完成；两位 AI 农民共同获胜 **7/12**。
- 同样牌局，三席位都是基础启发式时，农民获胜 **8/12**。
- 258 次真实调用、80 次策略介入；整步平均 51.8 ms、最高 112.5 ms；最大输入 504 tokens。

这组结果没有表现出稳定的团队增强，说明单席位改进不能直接外推到两个新策略的配合。样本很小，不能据此断言显著变强或变弱；但也不能隐去不利结果。更完善的农民协作与更强对手评测是后续工作。

上述两个最终评测合计 72 局真实模型对局、932 次出牌推理。基础启发式基线没有读取真实对手手牌；当前策略也只在可见信息一致的采样世界中模拟。

## 浏览器验收

在临时 localhost 服务中，经真实 UI 完成一整局并验证：

- 叫 3 分后，地主取得底牌，农民身份正确更新；
- “提示”选中飞机带对，点击“出牌”后正确移除 10 张牌；
- 两位 AI 顺序行动，两次过牌后恢复人类领出；
- 选择不同点数的两张单牌被拒绝，手牌、回合和选择保持，可纠正后继续；
- 提示出牌/过牌推进到农民胜利，停止后续 AI 行动；
- 底分 3、无炸弹、无春天，结算人类地主 -6、两位农民各 +3；
- 游戏结束才展示其他玩家剩余手牌；
- 刷新恢复同一局结算，下一局保留累计分数并隐藏新底牌；
- 玩法弹窗可打开和关闭；未发现 JavaScript 错误。

## 已知边界与下一步

- 模型没有斗地主专项训练。它的原始首选仍常需要纠正，不能把组合策略的结果叫作“纯 Laya 牌力”。
- 默认只采样 6 组未知牌，分布噪声较大；增加样本不保证必然增强。
- 54 ply 模拟使用基础启发式，不是对抗最优搜索；采样评分不是校准胜率。
- 候选只保留最多 6 项，可能丢失长程更佳走法。最少拆牌手数只描述自行出牌，不等于真实对局所需回合数。
- benchmark 固定地主，未衡量叫分策略；不会因为完整对局正常结束就声称叫牌最优。
- 尚未与 DouZero、专业引擎或真实玩家群体做系统对比。
- 后续应先扩大独立牌局和角色交叉评测，改进农民协作，再考虑限时残局搜索、专用策略基线或蒸馏训练。
